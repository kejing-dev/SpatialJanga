# Tower Wood Block Stacking Game

产品需求文档 PRD · v0.1 · 2026-09-16 · 待评审

## 1. 产品定义

一款运行于 PICO Shared Space 的单人空间叠木塔游戏。玩家用手势抓住塔身木块，缓慢抽出并放到塔顶，在逐渐不稳定的结构中挑战个人最高成功步数。

**核心体验：看清支撑关系 → 试探木块 → 抽出 → 移到塔顶 → 松手 → 等待稳定。**

产品采用 PICO Spatial SDK 构建空间场景与交互，以 PICO Spatial UI 承载界面，统一使用 Noto Sans 字体。Shared Space 在本产品中指应用与系统及其他应用共存的空间模式；本版只有一名玩家，不包含多人房间、联机或共享物理状态。

本文件是产品定义与验收基线，不代表 SDK 能力或真机效果已经验证。目标头显、PICO OS、Spatial SDK 和 Spatial UI 的具体版本在技术预研中锁定。

## 2. 用户、场景与目标

- **目标用户：**希望在空间设备中获得轻量、直观、无需手柄学习成本的休闲游戏体验的人。
- **主要场景：**坐姿或站姿短时游玩；木塔放在前方自然伸手可达的位置；每局预期 3–10 分钟，可随时暂停。
- **用户目标：**理解木塔受力，完成更高难度的抽取，并超过自己的历史最佳。
- **体验目标：**动作可预期、失败原因可理解、追踪异常不造成不公平失败。

空间价值来自立体观察、手部位姿和连续物理反馈：玩家可以从不同角度观察接触与倾斜，用抽取方向和速度影响塔身。平面版本需借助旋转视角及鼠标拖动间接表达这些动作；规则、设置、成绩仍使用简洁二维 UI。

**设计假设：**默认单手抓取，左右手均可；第二只手不能扶塔。初始采用紧凑木塔以降低伸手疲劳。以上属于待用户测试验证的产品选择。

## 3. 方案选择

| 方向 | 布局与交互 | 优势 | 风险与结论 |
| --- | --- | --- | --- |
| A · 桌面木塔 | 紧凑 Volumetric 木塔，侧边少量 Spatial UI；近距离直接抓取 | 坐姿可玩、注意力集中、占用空间小 | 需解决远侧木块可达性；选作主方案 |
| B · 绕塔立台 | 站立绕行独立立台，从不同方向抽块 | 空间观察价值强，接近实体玩具 | 依赖房间面积，绕行负担大；暂不采用 |
| C · 叠塔练习桌 | Planar 步骤面板加邻接小木塔 | 入门清晰，规则易理解 | 阅读抢占操作注意力；仅吸收为首次教学 |

视觉核心是自然木纹与塔身细微晃动。避免大型仪表盘、常驻规则墙和未经验证的“精确稳定百分比”；让木塔本身呈现风险。

应用提供自己的虚拟底座，不依赖识别真实桌面。用户不得被引导把身体重量支撑在虚拟物体上。

## 5. 游戏规则

### 5.1 初始木塔

- 54 块等尺寸长方体木块，18 层，每层 3 块，相邻层方向相差 90°。
- 初始设计尺寸为每块 75 × 25 × 15 mm，塔体约 75 × 75 × 270 mm。该数值用于首轮样机，必须通过手势精度测试后定稿。
- 初始物理场景需通过静置稳定检测才允许开始。无输入自行倒塌属于缺陷。
- 所有木块保持一致的基础物理参数；初版不引入隐藏随机摩擦或随机结构缺陷。

### 5.2 合法抽取

- 只能抓取最高完整层以下的木块。最高完整层及其上方未完成层均不可抽取。
- 任意时刻最多持有一块；先释放并完成当前回合，才能选择下一块。
- 抓取前允许试探不同合法木块。抓取后可以缓慢拉出、推回或改变方向，但所有接触持续参与物理模拟。
- 木块未完全离塔时，可以放回原位置并松手；若恢复稳定且没有散落木块，本次算作取消试探，不计步。
- 完全离塔后，该块成为本回合唯一目标，必须放到合法塔顶位置；不得更换另一块。
- 另一只手不能扶塔、推塔或同时抓取第二块。未抓取的手不施加物理冲击，以减少误碰。

### 5.3 合法堆叠与计分

- 塔顶每层最多 3 块，方向与下方完整层垂直；先填满当前顶层，再开启下一层。
- 抓取块接近塔顶时显示低对比度目标轮廓，表示朝向与可放区域；提示不施加吸附力，也不替玩家摆正。
- 放置后需同时满足：目标块脱离手部、处于合法顶层区域、接触支撑合理、无明显穿透、全塔连续稳定达到判定时长。
- **一次完整且合法的“抽出—放置—稳定”计 1 步。**分数不按抓取次数、短暂层高或用时增加。
- 若木块停在塔顶但位置或朝向不合法，显示“调整这块木块”，仅允许重新抓取该块；不计分且不能开启下一回合。
- 木块放出后尚未稳定时，允许重新抓取本回合目标块纠正；明确失败事件发生后不得撤销。
- 不设倒计时。用时只作结算信息，暂停和系统中断不计入有效时长。

### 5.4 失败与结束

- 本回合目标块脱手后掉到底座或落入底座以下回收区，判定“木块掉落”。原位取消试探不属于掉落。
- 任一非目标木块从塔身脱离并掉到底座或回收区，判定“木塔倒塌”。初始底层正常接触底座不触发失败。
- 单纯晃动、倾斜或短暂低速运动不立即判负；失败基于接触、位置和持续运动等物理证据组合。
- 失败只触发一次。保留短暂倒塌动画后结算；只统计此前已提交的成功步数。
- 主动重开需确认。用户关闭应用时保留最后已完成回合；重新进入提供“继续上次”或“新开一局”。
- 木塔达到可玩体积上限时，在完成当前回合后显示“已达到本局高度上限”，作为正常完成结算；不在持块或晃动过程中缩放场景。

## 6. 手势交互契约

| 阶段 | 玩家动作 | 系统反馈及约束 |
| --- | --- | --- |
| 发现 | 手靠近合法木块 | 只高亮一个候选块，轮廓清晰但不盖住木纹 |
| 抓取 | 在候选区域内捏合并保持 | 目标确认、轻木声；持续绑定同一块，避免候选跳变 |
| 抽取 | 保持捏合缓慢移动 | 使用受约束的物理抓取，碰撞可阻挡木块；不直接穿透相邻块 |
| 移动 | 木块完全离塔后移动手 | 允许自由空间位移和旋转，目标块持续可见 |
| 放置 | 张开手指释放 | 按释放位姿与受控速度进入自由物理，开始稳定检测 |
| 纠正 | 稳定前再次抓取目标块 | 中止本次稳定计时，重新调整，避免重复计分 |

**选择原则：**扩大的是候选命中区域，不扩大碰撞实体；候选重叠时优先实际接触/最近目标，并用迟滞避免抖动。不允许在远处捏合就把木块瞬移到手里。

**无实体阻力的补偿：**被阻挡时限制木块实际移动，以轮廓与轻摩擦声提示阻力；手与木块偏离过大时冻结并提示重新对准，避免积累弹簧能量后突然弹飞。

**手势与系统操作分离：**抓取仅在塔体交互区域生效；点击 Spatial UI 时不同时抓块。系统保留手势不得复用。重开按钮与主抓取路径分离。

## 7. Shared Space 布局与舒适性

主场景为一个 Volumetric 游戏体积；规则、暂停和结算由邻接 Planar Spatial UI 表面承载。最终容器组合及输入支持必须经目标 SDK 预研确认。

| 对象 | 初始设计值 | 行为 |
| --- | --- | --- |
| 游戏体积 | 默认 0.40 × 0.60 × 0.40 m（宽高深）；初版固定此规格 | 容纳抽取、顶端堆叠与局部倒塌；物理尺寸不随 UI 缩放改变 |
| 虚拟底座 | 0.24 × 0.24 m | 明确塔体落点与场景边界 |
| 初始位置 | 身体前方约 0.45–0.65 m，用户确认舒适高度 | 支持坐姿与站姿，不要求过肩抬手或身体前探 |
| UI 表面 | 默认 360 × 240 dp；最小 320 × 220，最大 480 × 360 dp | 塔侧下方，避免遮挡塔顶；长内容在面板内滚动 |

上述米制范围是样机起点，dp 不直接换算为固定物理长度；可读性、可达性、视野与窗口裁切需在真机验证。

```text
                 [塔顶放置区域]
                    木 塔
                    木 塔       当前步数 · 个人最佳
                 [虚拟底座]     [暂停] [位置]

                         玩家
```

- 场景保持稳定空间位置，不持续跟随头部。
- 调整位置、朝向仅在暂停且没有活动抓取时进行；冻结整个场景并作为整体移动，确认后恢复，不能借移动底座改变受力结果。
- 需要操作远侧木块时，可在稳定回合边界调整整个场景朝向；不要求用户绕行，也不允许在物理运动中旋转塔体。
- 活跃游玩只显示当前步数、个人最佳与必要控制；帮助与设置按需展开，不添加常驻顶部菜单带。
- 失去应用交互焦点时暂停计时、输入和物理。Shared Space 下的焦点通知及生命周期能力列为技术验证项。

## 8. 页面、状态与关键流程

| 状态 | 主要内容/动作 | 进入与退出 |
| --- | --- | --- |
| 准备 | 木塔预览、开始/继续、位置、帮助 | 放置确认后进入教学或可抓取 |
| 首次教学 | 依次练习选择、抓取、抽出、塔顶释放 | 使用独立练习塔，不计个人纪录；可跳过 |
| 可抓取 | 成功步数、可选块反馈 | 合法捏合进入持块；暂停进入暂停态 |
| 持块 | 当前目标与抽取/放置提示 | 释放后进入稳定检测或原位取消检测 |
| 稳定检测 | “等待木塔稳定” | 合法稳定则提交一次分数；错误摆放要求调整；掉落则失败 |
| 暂停 | 继续、位置、声音、重开、返回首页 | 继续前倒数提示；重开确认后清零本局 |
| 追踪恢复 | “暂时看不到你的手”及恢复引导 | 可靠追踪恢复后明确继续；超时提供恢复稳定回合 |
| 结算 | 本局步数、历史最佳、有效用时、结束原因 | 再来一局或返回首页 |
| 加载/恢复失败 | 可理解原因、重试、新开一局 | 不静默清除损坏或版本不兼容存档 |

**首玩路径：**启动 → 放置木塔 → 三步教学 → 第一局 → 倒塔结算 → 再来一局。

**确认策略：**暂停、继续、打开帮助不确认；重开、放弃未完成局确认。确认弹窗打开期间冻结物理，避免阅读时继续倒塔。

## 9. 追踪丢失、中断与保存

- 追踪质量不足时冻结全塔、当前抓取和计时，不把丢失追踪视为松手。
- 恢复时显示冻结木块位置，引导原抓取手重新接近并捏合后继续；禁止将木块瞬间拉到恢复后的手部位置。
- 长时间无法恢复时允许退回最近一次已完成回合，并标记本局“恢复局”。恢复局可继续娱乐，但不刷新标准个人最佳，以避免异常恢复形成重试优势。
- 正常暂停/继续若保留完整当前状态，不标记为恢复局；活动持块期间不开放位置调整。
- 每次成功步数提交后，原子保存木块布局、分数、有效用时、规则版本和必要的物理状态信息；计分事件有唯一回合标识，避免重复提交。
- 进程退出后从最后稳定回合恢复，明确说明“继续上次已完成回合”，并按恢复局规则处理。不存在存档则直接新开局。
- 崩溃恢复、存档损坏、追踪丢失均不能自动判定玩家失败或覆盖有效历史最佳。

## 10. 视觉、字体与音频

**美术方向：**浅暖原木、端面纹理、细微倒角、柔和接触阴影；木块边界与层间方向必须清晰。底座使用安静中性色，减少与木塔竞争。

**界面：**采用 PICO Spatial UI 标准按钮、提示和对话框；窗口根背景使用系统玻璃材质，遵循 Vibrant 自适应文本层级。品牌暖木色只用于装饰或克制强调，不硬编码整块不透明窗口背景。

**字体：**全部产品文案和数字使用 Noto Sans；标题与正文采用同一家族不同字重。建议标题 24 dp、成绩 32 dp、正文 16 dp、辅助文字 14 dp；按钮命中区域不小于 56 × 56 dp，间距优先 8/16/24/32 dp。字体加载及中文覆盖在工程阶段验证，缺字回退不应改变可读性与版式。

**反馈：**候选块用轮廓，已抓取块用持续状态，非法区域附“此层不可抽取”等文字；不能仅以红/绿区分。稳定成功提供短促轻音和步数更新；倒塔采用有层次的木块碰撞声，避免过大音量。声音可关闭；本版不依赖手部触觉反馈。

主要文案示例：“捏住一块木块”“慢慢抽出来”“放到塔顶后松手”“等待木塔稳定”“调整这块木块”“暂时看不到你的手”“本局完成 8 步”。

## 11. 初始调参建议

以下是实现起点，不是 SDK 官方参数或发布承诺；通过真实设备数据调整。

| 参数 | 初始建议 | 验证目的 |
| --- | --- | --- |
| 稳定判定持续时间 | 连续 1.0 秒 | 排除短暂静止后继续倒塌 |
| 稳定运动阈值 | 活跃塔体线速度 <0.01 m/s、角速度 <0.05 rad/s，结合支撑检测 | 防止悬空或穿透状态误判成功 |
| 塔顶朝向容差 | 与目标轴偏差 ≤10° | 可理解且无需精密手部控制 |
| 追踪恢复超时提示 | 3 秒后显示稳定回合恢复选项 | 短时遮挡不立即中断整局 |
| 空闲稳定测试 | 无输入静置至少 60 秒 | 排除物理配置导致的自倒 |

支撑区域、位置容差、摩擦、质量、阻尼、抓取刚度及释放速度上限需联合调优。不得只用“距离目标槽足够近”作为合法堆叠依据。

## 12. 技术边界与预研门槛

| 模块 | 职责 | 必须验证 |
| --- | --- | --- |
| Spatial SDK 场景 | 木块、底座、空间位置与容器生命周期 | Shared Space 下 Volumetric 尺寸、裁切和邻接 UI 能力 |
| 手势输入 | 候选、抓取、释放、左右手及追踪状态 | 近场精度、遮挡、系统手势竞争及焦点通知 |
| 物理与规则 | 连续碰撞、抓取约束、休眠、支撑与失败判定 | 使用 SDK 支持能力或兼容物理方案；不预设存在特定接口 |
| Spatial UI | 准备、暂停、教学、结算及设置 | 目标版本组件、玻璃材质与字体路径 |
| 本地存储 | 稳定回合、最佳成绩、设置与版本迁移 | 原子写入、损坏处理及旧存档兼容 |

先用完整 54 块塔完成“抓一块—抽出—放回—稳定”的真机技术样机，再进入完整美术制作。若微小木块选择不可靠，优先验证统一放大比例与舒适范围；如果 Shared Space 容器、手势或物理无法满足核心体验，回到产品评审，不静默切换 Full Space。

## 13. 验收与衡量

以下为拟定发布门槛，需在明确目标设备与测试样本后确认。

| 领域 | 验收条件 |
| --- | --- |
| 规则 | 54 块及层方向正确；最高完整层保护；非法放置不计分；每回合最多加 1 步 |
| 抓取 | 左右手可完成完整回合；同时最多抓 1 块；无跨块跳选、穿塔瞬移或明显弹飞 |
| 中断 | 覆盖持块、稳定检测、结算前的追踪丢失与切后台；无误释放、重复计分或自动判负 |
| 物理 | 完整塔无输入静置 60 秒不倒；连续 10 局无持续穿透、异常自爆或越界失控 |
| Shared Space | 不主动切换 Full Space；空间调整不改变塔内相对布局；失焦行为符合预研确认的系统能力 |
| UI 与舒适 | 坐姿和站姿都可完成一回合；必要文案无遮挡；不同环境亮度下可读；Noto Sans 正确呈现 |
| 性能 | 在锁定设备的目标刷新率下，95% 帧不超过对应单帧时间预算；倒塔时无持续卡顿 |
| 存档 | 正常保存可恢复；恢复局不刷新标准纪录；损坏数据有明确处理路径 |

首轮可用性测试建议至少 8 名新用户：≥80% 在 3 分钟内独立完成首个成功回合；≥80% 能解释失败原因；系统导致的误抓或误释放占已记录抓取尝试的比例目标 <5%。这些是验证目标，不能作为已达到的数据。

建议记录事件：开始、教学步骤完成、抓取成功/失败、回合提交、追踪中断、暂停、恢复与结束原因。通过事件评估首步成功率、教学流失、平均步数与中断频率；不采集相机画面或原始手部轨迹作为默认分析数据。

## 14. 交付阶段与待确认项

1. **体验预研：**锁定设备/系统/SDK 版本，验证 Shared Space 容器、手势输入、54 块物理和最小可抓尺寸。
2. **核心可玩版：**打通完整规则、计分、倒塔、左右手和异常暂停；达到规则与物理验收。

## 当前实现补充（2026-09-17）

- 字体更新为 Noto Sans SC，覆盖中文与拉丁字符，随 APK 打包。
- Blender 原创木块为 75×25×15 mm，54 块 / 18 层；碰撞盒略内缩以减少毫米级接触抖动。
- 首版采用回合式休眠：静止局面使用静态碰撞盒；抓持块限速跟随手势，上方启用动态刚体，松手后为所选块恢复动态刚体；成功放稳后恢复静态。抓取前段限制长轴移动，但通用扫掠碰撞和真实手势手感尚未验收。此模型优先保证 XR 游戏稳定性，不宣称是工程级或全塔连续物理仿真。
- 中断与暂停冻结当前姿态；有未完成木块时，恢复后需重新抓取同一块。
- 恢复最近完成的回合进入练习模式，不更新最高纪录。
- 当前容器为 0.70 × 0.60 × 0.40 m，为并排木塔与操作面板预留宽度。
- UI 在同一个 Volumetric WindowContainer 内通过 AttachmentPanel 呈现。环境房间来自系统 Shared Space，不由应用绘制。
